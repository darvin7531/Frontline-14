## О проекте

Frontline 14 превращает привычный мир SS14 в поле **продолжительной войны двух фракций**. Победа зависит не только от перестрелок: кто-то добывает железо, кто-то перерабатывает его, производит снаряжение, доставляет припасы грузовиком и удерживает базы.

- **Общий физический мир:** персонажи, грузы, техника и стратегические объекты существуют непосредственно на карте.
- **Территориальная война:** контроль над территориями определяется состоянием объектов `Town Hall`; победа рассчитывается по очкам территорий.
- **Логистика имеет значение:** оружие, боеприпасы, медицина и припасы для возрождения проходят через производство и склады.
- **Война переживает технический рестарт:** сохраняется выбранное стратегическое состояние кампании, включая транспорт и его груз.
- **RP — по желанию:** проект не требует станционных профессий, обязательного отыгрыша ролей или стандартного раундового цикла SS14.

### Игровой цикл

1. **Добыча сырья** — получение ресурсов из месторождений.
2. **Переработка** — превращение сырья в материалы.
3. **Фабрика** — производство снаряжения и припасов.
4. **Ящики снабжения** — физические партии готовой продукции.
5. **Грузовик** — доставка ящиков и материалов.
6. **Склад базы** — приём и хранение запасов.
7. **Снабжение и бой** — получение предметов и возрождение за Soldier Supplies.
8. **Контроль территорий** — уничтожение и восстановление стратегических баз.

Поставка `Soldier Supplies` позволяет оплачивать возрождения на снабжённых базах. Уничтожение `Town Hall` оставляет руины; восстановление требует `BasicMaterials` и может изменить владельца территории.

## Что уже есть в `master`

| Направление | Реализованная основа |
| --- | --- |
| **Кампания и фракции** | Режим `PersistentWar`, `WarId`, две фракции, выбор стороны, состояние и завершение войны. |
| **Территории** | Пять настроенных территорий, физические `Town Hall`, разрушение и восстановление, очки победы. |
| **Ресурсы и промышленность** | Ресурсные поля, физическое сырьё, `Refinery`, `BasicMaterials`, `Factory`, рецепты и производственные очереди. |
| **Снабжение** | Запечатанные ящики оружия, боеприпасов, медицины и `Soldier Supplies`; публичные склады баз с агрегированными остатками. |
| **Возрождение** | Выбор доступной базы и расход `Soldier Supplies` при возрождении. |
| **Транспорт** | Управляемый `FrontlineLogisticsTruck` с местом водителя, 10 физическими грузовыми слотами, дорожными модификаторами скорости и направленными спрайтами. |
| **Стратегическое сохранение** | Восстановление состояния баз, складов, ресурсных полей, фабрик, переработчиков, грузовиков и поддерживаемого груза при техническом рестарте. |
| **Планетарные ассеты** | Первичный набор грунта, травы, песка, асфальта, бетона, грунтовой дороги и декораций, перенесённых с сохранением атрибуции. |
| **Инструменты разработки** | Тестовая карта, проверка инвариантов `PersistentWar`, интеграционные тесты, admin/debug-команды и фильтр `Frontline` в меню спавна сущностей. |

**Пример текущей экономической цепочки:** `FrontlineRawIron` → `BasicMaterials` → производство физического ящика → перевозка → сдача на склад базы.

> [!NOTE]
> **Стратегическое сохранение ≠ полное сохранение мира.** Snapshot охватывает определённые системы и объекты, а не произвольные изменения каждой сущности или тайла. Основной сценарий — штатный технический рестарт; непрерывное аварийное восстановление мира ещё не заявлено.

## Текущие ограничения и ближайшие задачи

Цель следующего этапа — **закрытый технический тест на 20 игроков (10 на 10) на одном фронте**, а не немедленный запуск большой постоянной войны.

| Приоритет | Задача |
| --- | --- |
| **Высокий** | Построить полноценную игровую карту одного фронта с базами, дорогами, добычей, производством и маршрутом снабжения. Сейчас в репозитории используется прежде всего `Resources/Maps/Frontline/base_test.yaml` — техническая тестовая карта. |
| **Высокий** | Усилить серверные проверки фракционной принадлежности при работе со складами баз. |
| **Высокий** | Проверить весь игровой цикл и стабильность при одновременном участии 20 игроков; наличие интеграционных тестов не заменяет нагрузочный тест. |
| **В работе / планируется** | Переработать интерфейсы склада, переработчика и фабрики: компактные сетки предметов, понятные рецепты и состояние очередей. |
| **Планируется** | Разделить производственные заказы на общую очередь и личные очереди игроков. Сейчас используются существующие очереди машин без такой модели владельцев. |
| **Планируется** | Расширить практическое пехотное снабжение и добавить минимальный обзор состояния территорий. |

**За рамками ближайшего MVP:** автоматическая заморозка фронта при низком онлайне, тяжёлая техника, топливная экономика, масштабная система укреплений и полноценное технологическое развитие. Эти идеи не обозначены как уже реализованные функции.

## Технологии и структура

Основной язык — **C#**. Проект использует системы **RobustToolbox / Space Station 14**, включая ECS, сетевую синхронизацию, физику, контейнеры, инвентарь, взаимодействия, прототипы, локализацию и UI. Вместо переписывания движка проект развивает собственный игровой контент.

| Где искать | Назначение |
| --- | --- |
| `Content.Server/War/` | Серверные системы войны, логистики и сохранения. |
| `Content.Shared/War/` | Общие компоненты, прототипы и сетевые сообщения. |
| `Content.Client/War/` | Клиентские интерфейсы Frontline. |
| `Resources/Prototypes/War/` | Игровые объекты, ресурсы, рецепты, транспорт и территории. |
| `Resources/Prototypes/Frontline/` | Планетарные тайлы и декорации. |
| `Resources/Maps/Frontline/` | Карты проекта и тестовый полигон. |
| `Resources/Textures/Frontline/` и `Resources/Textures/_Frontline/` | Импортированная графика и её атрибуция. |

### Начало работы

Для разработки нужен подходящий .NET SDK (см. `global.json`), Git и зависимости, используемые SS14.

```bash
git clone https://github.com/darvin7531/Frontline-14.git
cd Frontline-14
python RUN_THIS.py
dotnet build SpaceStation14.sln
```

Для локального запуска предусмотрены `runserver.sh` / `runclient.sh` (Linux) и `runserver.bat` / `runclient.bat` (Windows). Порядок инициализации и требования движка также описаны в [документации SS14](https://docs.spacestation14.com/).
